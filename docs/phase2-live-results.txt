EXTENSION A - BACKUP DNS: VERIFIED
Primary project dnsmasq was stopped, the OS resolver cache flushed, and an explicit query
to the stopped primary failed. A fresh system-resolver query went to 10.7.12.137 and was
answered with 10.7.6.136; three domain-based, certificate-validated HTTPS requests returned 200.
The first fallback request took roughly three seconds: failover is not instantaneous.
Primary DNS was restored and answered again.
Learning: name resolution can survive one DNS service failure; cached answers alone are
not evidence that a backup resolver was used.
Evidence: dns-failover.txt and dns-failover.pcapng.

EXTENSION B - TTL / CACHE: VERIFIED WITH CONTROLLED CLIENT CACHE
A temporary ttl.team1.test record on primary DNS changed from 10.7.6.136 to 10.7.23.11.
A separate client-side caching resolver on 127.0.0.1:1053 retained the old answer with
TTL 29, 24 and 13 seconds; after 33 seconds it fetched the new address with TTL 30.
macOS itself retained the earlier answer longer in this trial; a manual OS cache flush
updated it to the new address. After reversing the server record, both caches retained
the newer cached address until explicitly flushed, then returned the restored old address.
The temporary record and client cache were removed, original application records restored,
and dual client DNS configuration restored. Do not claim macOS switched at exactly 30 seconds.
Learning: authoritative records, client caches and OS cache behavior are separate observations.
Evidence: dns-ttl.txt and dns-ttl.pcapng.

EXTENSION E - EDGE MIGRATION: LIVE CUTOVER AND BASELINE RESTORATION VERIFIED
Independent standby nginx runs on Mac 1 (10.7.23.11), separate from Ansh's active edge.

standby TLS trust and origin firewall permissions are both required for a working migration.
Evidence: edge-cutover.txt and edge-cutover.pcapng; standby-preflight.txt.
